# C/C++ 编码规范

本规范用于仓库中的手写 C/C++ 代码。当前第一阶段的自动格式化范围只有：

```text
firmware/stm32/f411_watch/user/**
products/f411_watch/core/**
```

CubeMX 生成区、STM32 HAL/CMSIS、FreeRTOS、FatFs、USB middleware、ESP-IDF
和其他第三方代码不属于本规范的自动格式化范围。不得为了格式化而修改这些目录。

## 格式化基线

- 使用 4 个空格缩进，禁止 Tab。
- 建议代码行不超过 100 列；必要时由 clang-format 换行。
- 函数定义的左大括号单独放在下一行。
- `if`、`for`、`while`、`switch` 等控制语句的左大括号与语句同行。
- 所有控制分支都使用大括号，即使分支中只有一条语句。
- 指针采用右绑定写法，例如 `const uint8_t *data`。
- include 不由格式化工具自动排序，保留有意义的分组和顺序。

`.clang-format` 位于仓库根目录，是项目级格式配置。格式化工具只能接收明确的手写文件列表，不能对仓库根目录递归运行。

## 命名

- 文件名、函数名、变量名使用 `snake_case`。
- 编译开关和预处理宏使用 `UPPER_SNAKE_CASE`。
- 公共函数使用模块前缀，例如 `watch_lcd_init()`。
- 只在单个 `.c` 文件使用的函数和变量声明为 `static`。
- 文件内的静态状态变量使用 `s_` 前缀，例如 `s_dma_transfer_active`。
- enum 类型使用项目确认的 `_t` 后缀，例如 `watch_lcd_transfer_result_t`。
- 项目自有 struct 使用 typedef，并使用 `_t` 后缀，例如 `watch_display_config_t`。
- enum 成员使用大写并带类型或模块前缀，避免产生全局名称冲突。

## 模块和头文件

- 一个模块由一对主要的 `.c/.h` 文件组成，模块应当表达一个清晰的职责。
- 头文件使用 include guard。
- `.c` 文件首先 include 自己的头文件，然后再 include 其他头文件。
- 头文件只暴露调用方需要的类型和函数，避免把实现细节放入公共头文件。
- 应用层不直接访问 HAL、GPIO、SPI 句柄或芯片寄存器；硬件细节留在板级模块。

## 类型、常量和宏

- 寄存器、协议、存储格式和硬件数据使用 `stdint.h` 中的固定宽度整数类型。
- 表示布尔状态使用 `bool`，表示对象大小或容器长度时使用合适的无符号长度类型。
- 不会改变的数据使用 `const`。
- 优先使用类型明确的 `static const` 常量；宏主要用于编译开关、条件编译和必须由预处理器处理的内容。
- 宏参数和表达式使用括号；多语句宏使用 `do { ... } while (0)`。
- 能用函数、enum 或 const 表达的内容，不使用宏替代。

## 控制流和函数

- 无参数函数显式写 `(void)`。
- 只在模块内部使用的函数声明为 `static`。
- 结构体参数在合适时通过指针传递，避免不必要的栈复制。
- 针对项目内部封闭 enum 的 `switch` 覆盖所有枚举值；对于外部输入或可能损坏的数据，使用明确的错误处理分支。
- 返回值和 HAL 状态不能无意丢弃；确实有意忽略时使用显式转换或注释说明。
- 注释重点说明“为什么”，不重复描述代码已经清楚表达的“做什么”。

## 工具边界

编码规范由三部分共同维护：

1. `.clang-format` 负责缩进、括号、换行等机械格式。
2. CMake 的 `format` target 只修改白名单文件，`format-check` 使用 clang-format 的非修改检查模式。
3. 编译器、Cppcheck 和代码评审负责 API、资源、并发和错误处理等语义问题。

`// clang-format off` 只允许用于确实需要保持表格或硬件顺序的手写代码，并应当尽量缩小范围。生成代码不通过添加格式注释来管理，而是直接排除在格式化白名单之外。
